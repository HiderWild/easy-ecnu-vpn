# 平台真实业务流活动

[业务流优先的宿主修复治理政策](business-first-host-repair-policy.md) 是本活动的**唯一活跃正文**。
本页只把政策落到一次受影响原生宿主的真实用户业务流，不另设抽象或跨宿主的验收条件。

## 进行方式

1. 记录 Requirement ID、目标宿主、实际用户路径和准备验证的可观察结果。
2. 先运行相关模块测试，再在目标原生宿主执行该真实用户业务流；两类结果分别记录，不能互相冒充。
3. 发生错误时，保留实际错误、当前环境和可重现步骤；原因未知时如实写明未知，并提供重试、重启、
   重装或日志反馈等下一步。
4. 若发现明确的 Common、共享构建、契约或测试问题，直接在相应范围修补。宿主记录只说明观察事实、
   当前修补和当前活动接线；是否形成整合候选由专门整合工作独立决定。
5. 只有该宿主真实业务流跑通时，才可以声明该宿主当前路径通过。未运行或失败是缺陷证据，不得伪造
   通过，也不自动阻止其他开发。

## 活动边界

本活动不得因未知或未建模状态扩大为穷举、补偿或完整性证明，也不得建立跨模块、跨系统、跨进程
或跨宿主联合状态机。局部模块的有限校验和针对具体问题的排查仍可使用，但只说明其明确边界内的
结果。

双轨版本可共存；每个业务路径只接当前选定的一版。重新接线或恢复未接线版本后，必须在相关原生
宿主重新运行真实用户业务流。GitHub Actions 不用于本活动的 CI、验收或真实宿主证据。
